# 看板排版与需求完整性复核

结论：原版存在信息层级、字号和移动端宽表阅读问题，需要优化。本轮已完成一组明确的界面优化；**完整页面不等于完整数据覆盖，原始需求仍有部分未完成项**。最新统计口径仍为折扣码/联盟链接优先、无两类证据待审核、播放量至少1000；周报保持精简五列爆款表。

## 排版问题与本轮调整

| 问题 | 影响 | 本轮处理 |
|---|---|---|
| 总览分析长文默认全部展开 | 数据和行动重点被重复说明挤到下方 | 总结默认可见，事实/建议/限制可展开；不删除分析内容 |
| 视频行混入全部证据、三个时间、7/30天表现和多项指标 | 行高且辅助文字只有10px，难以比较 | 紧凑五列列表＋只读详情窗口，辅助字号提高到12px |
| 全球筛选缺少常驻字段名，统计范围选项过长 | 选中值截断、不同宽度随意换行 | 网格布局、字段标签、简短选项与明确口径；增加重置 |
| 手机筛选与导航占首屏过多 | 首块数据接近首屏底部 | 手机默认收起筛选，保留当前选择摘要；导航三列 |
| 时间戳显示原始ISO长字符串 | 时间、时区和数据年龄难辨 | 统一按报告时区显示，原始ISO保留在时间悬停提示，完整时间见详情 |
| 数字和日期在小屏按字符断行 | 80,000或日期被拆开，影响理解 | 数字/日期保持整段，宽表在局部滚动并给提示；页面不横向溢出 |
| 规则与相关查询直接输出JSON | 非技术团队难以阅读 | 规则改为表格，相关查询改为“热门/上升”文字；高级配置默认折叠 |
| 模块切换保留上一页滚动位置 | 新页面可能从中间开始 | 切换模块回到页首，导航标记当前页 |
| 请求失败后仍可导出旧筛选结果 | 用户可能误认已更新 | 加载/失败时禁用导出，成功更新后恢复；失败保留上次结果并提示 |

补充展示：内容形式数量和占比；每查询/归一化批次独立的12周热度图，缺失周留空；视频详情补充内容不可用状态、语言依据、7/30天观测时间和互动率公式。没有更改判定、1000播放门槛或周报范围。

本轮保留的界面限制：手机上的复杂列表仍需局部横向滚动；红人库、配置录入仍偏表格/高级JSON，尚未提供全部字段的友好表单；没有交互排序、分页或万人级记录性能验证。

## 测量与验证说明

使用同一组隔离DEMO视频，分别在1366×768和390×844检查六个页面。原始测量在 `layout-audit/before.json`，优化后在 `layout-audit/after.json`。前后截图均带DEMO说明，不代表真实竞品数据。

- 原桌面总览内容区2029px，其中分析区1373px，占约68%。优化后约1201px，内容区缩短约41%。
- 原手机总览内容区3370px，优化后约1698px，约缩短一半；首块数据由约743px提前至约523px（实际高度随数据/提示长度变化）。
- 手机视频首行由315px降至约122px，辅助文字从10px提高到12px；详细证据与观察期数据仍可打开。
- 两种尺寸六页均检查页面无横向溢出；宽表允许局部滚动。趋势页面另外加入11个合成周数据＋1个缺失周验证绘图，不能拿前后的趋势页面长度直接比较。

复测命令：`python3 scripts/layout_check.py`、`python3 scripts/browser_check.py`。前者验证详情、12周缺失点、字号、页面边界、重置、周一定位、分析展开、导航状态以及请求失败后的导出保护；后者验证导入、审核、配置和导出操作。截图见 `layout-audit/`，更新后的通用看板截图见 `dashboard-v2.png`。

## 建议后续优先级

1. 数据覆盖：完成官网和官方账号核验；明确Instagram/TikTok及趋势的可用授权来源或固定导入流程。
2. 分析完整性：补齐品牌/平台/车型逐项周环比、红人合作内容效果汇总及国家/语言筛选。
3. 运营体验：友好录入表单、排序/分页、大数据量验证和目标电脑的自动启动验证。

不能把“页面都有”或“演示数据正常”当作三个平台持续自动监控全部上线。
